# Claude Code-ის 15 ბრძანება

!!! info "შენახულია: 2026-11-09"
    ბრძანებები ტერმინალის Claude Code-ში იწერება `/`-ით. ზოგი მათგანი ექსპერიმენტულია ან დამატებით რესურსს ხარჯავს. ეს აღნიშნულია შესაბამის ადგილას.

## სესია და საუბარი

`/btw`
:   გვერდით კითხვას სვამ ისე, რომ კითხვა და პასუხი მთავარ საუბარში არ ემატება. მაგალითად: „იმ კონფიგურაციის ფაილს რა ერქვა?“ პასუხობს უკვე არსებულ კონტექსტზე დაყრდნობით, დამატებით ფაილებს არ კითხულობს.

`/fork`
:   მიმდინარე საუბრის ასლს დამოუკიდებელ ფონურ სესიაში ქმნის. გამოგადგება, როცა ალტერნატიული გადაწყვეტის გამოცდა გინდა და ძირითადი მუშაობის გაგრძელებაც გჭირდება.

`/background`
:   მიმდინარე სესიას ფონზე გადაიტანს და ტერმინალს სხვა საქმისთვის ათავისუფლებს. მუშაობა შენს კომპიუტერში გრძელდება, ამიტომ კომპიუტერის გამორთვა ამ პროცესსაც გააჩერებს.

`/teleport`
:   ღრუბელში დაწყებული სესია შენს ტერმინალში გადმოაქვს, საუბრის ისტორიითა და სამუშაო branch-ით, რომ საქმე ადგილობრივად გააგრძელო.

## კონტექსტი და მოდელი

`/context`
:   გაჩვენებს, რა ავსებს კონტექსტის ფანჯარას. სასარგებლოა, როცა გინდა გაიგო, რამდენ ადგილს იკავებს საუბარი, ინსტრუქციები და სხვა ინფორმაცია.

`/skill-doctor`
:   გაჩვენებს, რა მოცულობის კონტექსტს იკავებს შენი Skills და რამდენად ხშირად გამოიყენება ისინი. ასე უფრო ადვილად გადაწყვეტ, რომელი დატოვო და რომელი გამორთო.

`/effort`
:   არეგულირებს, რამდენად ინტენსიურად იმსჯელოს მოდელმა. მარტივ ცვლილებასა და რთულ არქიტექტურულ ამოცანას ერთნაირი ძალისხმევა ყოველთვის არ სჭირდება. ხელმისაწვდომი დონეები მოდელზეა დამოკიდებული.

`/advisor` :material-flask-outline:{ title="ექსპერიმენტული" }
:   ძირითად მოდელს მეორე მოდელთან კონსულტაციის შესაძლებლობას აძლევს. მაგალითად, მიდგომის არჩევისას ან განმეორებით შეცდომაზე გაჭედვისას. კონსულტაციის მომენტს Claude ირჩევს. ფუნქცია ექსპერიმენტულია და დამატებით რესურსს მოიხმარს.

## გამართვა და ანალიზი

`/import`
:   Codex-იდან, Gemini CLI-დან ან Cursor-იდან პარამეტრების გადმოტანაში გეხმარება: ინსტრუქციები, Skills, MCP სერვერები და სხვა კონფიგურაცია. წინასწარ სანახავად გამოიყენე `/import --dry-run`.

`/fewer-permission-prompts`
:   წინა სესიებში განმეორებად, მხოლოდ წაკითხვის ტიპის Bash და MCP მოქმედებებს აანალიზებს და პროექტის დაშვებების სიას ავსებს. შედეგად, ნაკლებად ხშირად გეკითხება ერთსა და იმავეს.

`/insights`
:   შენს კომპიუტერში არსებულ ბოლო სესიებს აანალიზებს და HTML ანგარიშს ქმნის: რაზე მუშაობდი, სად გაჩნდა სირთულეები და რა შეიძლება გააუმჯობესო.

## კოდის შემოწმება

`/verify`
:   პროექტს აწყობს, უშვებს და ამოწმებს, მუშაობს თუ არა ცვლილება გაშვებულ აპლიკაციაში. განსაკუთრებით გამოსადეგია, როცა კოდი სწორად გამოიყურება, მაგრამ რეალური ქცევაც გინდა ნახო.

`/code-review`
:   ამოწმებს კოდის ცვლილებებს, კონკრეტულ PR-ს ან branch-ს და ეძებს შეცდომებს. `/code-review --fix` აღმოჩენილი პრობლემების გასწორებასაც სთხოვს.

`/ultrareview` :material-cash:{ title="ფასიანი" }
:   ღრუბელში რამდენიმე აგენტით უფრო ღრმა შემოწმებას იწყებს. ოფიციალური ძირითადი ფორმაა `/code-review ultra`; `/ultrareview` მისი ალტერნატიული სახელია. ეს რეჟიმი დამატებით ხარჯთან შეიძლება იყოს დაკავშირებული.

`/autofix-pr`
:   ღრუბლოვანი სესია აკვირდება Pull Request-ს, ანუ კოდის ცვლილებების გაერთიანების მოთხოვნას. თუ ავტომატური შემოწმება ჩავარდა ან რევიუერმა კომენტარი დატოვა, იკვლევს პრობლემას და მკაფიო გამოსავლის შემთხვევაში შესწორებას აგზავნის. საჭიროა Claude GitHub App-ის დაკავშირება.
